# Peloton Churn & Retention Intelligence

## Project Overview

This project is an end-to-end churn and retention analytics solution built using Python, PostgreSQL, Power BI, and Gemini API.

The objective is to understand why subscribers churn, identify high-risk members, analyze engagement and support behavior, and provide data-backed retention recommendations.

---

## Business Problem

Subscription businesses lose revenue when customers cancel.

This project answers questions such as:

- Which customers are more likely to churn?
- Does low workout engagement indicate churn risk?
- Is support contact associated with higher churn?
- Does churn increase near annual renewal periods?
- What are the major cancellation reasons?
- Which customers should be prioritized for retention?

---

## Key Findings

The analysis identified three important churn-risk signals:

1. Low recent workout engagement
2. Recent customer-support contact
3. Annual renewal stage

These are treated as associations and risk signals, not proof of causation.

---

## Business Recommendations

- Target members whose workout activity is declining
- Prioritize customers with recent support interactions
- Create retention campaigns before annual renewal periods
- Use engagement and support signals together to identify high-risk members
- Test retention actions through controlled experiments

## GenAI Retention Analyst

A Gemini-powered AI Retention Analyst was built to answer business questions.

Architecture:

User Question  
↓  
Verified PostgreSQL Results  
↓  
Gemini API  
↓  
Business-Friendly Answer  
↓  
Numeric Validation Guard  

The LLM does not calculate KPIs itself.

PostgreSQL is used as the source of truth, while Gemini explains verified results.

---

## LLM Validation

A Python validation layer checks numeric claims generated by Gemini.

If Gemini produces a number that is not supported by PostgreSQL evidence, the system returns a warning.

This helps reduce unsupported LLM-generated business claims.
